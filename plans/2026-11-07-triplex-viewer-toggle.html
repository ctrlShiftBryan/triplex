Triplex viewer toggle

A global toggle that opens 3D component files straight in the Triplex viewer, two per-file palette commands to switch between source and viewer, and a marker comment, kept up to date by a check built on Triplex's own 3D detection, that decides which files auto-open.

Goal and boundaries

In scope

  • The baTriplex.openInViewer setting and the BA Toggle - Triplex command, modeled on BA Toggle - Markdown (ctrlShiftBryan/ba-vscode-ext).
  • BA: Show Source and BA: Show Triplex Viewer for the current file.
  • The // @triplex-viewer marker and the ba-triplex-mark CLI (--check / --write).
  • Installing the CLI and the extension on every machine.
  • A consuming project adopting the markers, a check step and an agent rule (tracked privately in that project).

Out of scope

  • The VS Code e2e tests: no display on the build machine, and they already expect the old split layout (from 1c1c8d74). Left as they are.
  • A status bar item for the mode (a notification on flip only).
  • Persisting per-file choices across restarts.
  • Publishing the CLI to npm.
  • Global agent-rule changes.

How a file open is decided

1
A new source tab opens (Explorer, Quick Open, a link). Switching to an already-open tab never triggers anything.
2
Is baTriplex.openInViewer on? No → stay on source.
3
Has this file a per-file choice this session (Show Source / Show Triplex Viewer / Go To Definition)? Yes → follow it.
4
Do the file's leading comments (before the first import) contain // @triplex-viewer? No → stay on source.
5
Open the viewer in place of the source tab (same group, unsaved tabs untouched), showing the default export, else the last named export.

How markers get there

Agents can also add the marker by hand. // @triplex-viewer-ignore keeps a 3D file out, and --check stays green for it.

Implementation

Phase 1 · triplex fork

The marker check: ba-triplex-mark

  • New package packages/ba-triplex-mark with a bin. It imports Triplex's babel plugin from packages/@triplex/client/src/plugins/babel-plugin.ts (not exported from the published package) and runs it with babel.transformSync.
  • Find the export auto-open would show (the same rule as getFallbackExportName: default export, else last named export) and read its triplexMeta.root.
  • When the root inherits from a child component, resolve the child's import (relative paths, explicit extensions, tsconfig paths and package.json imports aliases) and classify it, with a cache and cycle guard.
  • Shared marker helpers (read leading comments, has marker, has ignore, add marker) usable from both the CLI and the extension.
  • --check <paths>: exit 1 and list each 3D file missing a marker. --write <paths>: add // @triplex-viewer as line 1 (before the first import), never remove a marker, skip files with the ignore comment.

Done when the unit tests in phase 4 for the classifier and CLI pass and pnpm typecheck, pnpm lint are green on Node 22.

Phase 2 · triplex fork

The extension: toggle, commands, auto-open

  • apps/vscode/package.json: the baTriplex.openInViewer setting (boolean, default false) and the three commands; when clauses on context keys for the palette, the title-bar button and the code lens.
  • A mode module with the decision logic as a pure function (inputs: setting, per-file choice, marker, tab event) so it unit-tests without VS Code.
  • Listen for newly opened source tabs (tabGroups changes); when the decision says viewer, reuse the triplex.start path from 1c1c8d74 so the viewer replaces the source tab.
  • The toggle flips the setting, shows a notification, clears per-file choices and reopens open marked tabs in the new mode (dirty tabs skipped).
  • Show Source / Show Triplex Viewer swap the current tab and record the per-file choice in memory. triplex.open-file (Go To Definition) records "source" for its target.
  • Set context keys on active-editor change: has exported component (inferExports), is viewer tab.

Done when the mode-decision tests pass and the extension typechecks and lints.

Phase 3 · triplex fork

Installing on every machine

  • scripts/install-fork-vsce.sh builds the CLI and installs it as ~/.local/bin/ba-triplex-mark before the extension step.
  • Install the extension into the newest ~/.vscode-server code-server if present, else the local code CLI, else print a note and skip. Keep the Node 22 re-exec and the TMPDIR fix.
  • Update apps/vscode/README.dev.md "Installing the fork" with the CLI and the toggle.

Done when the script runs and ba-triplex-mark --help works from a fresh shell.

Phase 4 · triplex fork

Tests

  • Marker detection: leading comments only, the ignore comment, files with license headers or directives.
  • The classifier on fixtures: direct three.js tags, R3F hooks, a DOM component, a component rendering <Canvas>, a multi-export file, and a cross-file chain through two wrapper components.
  • CLI --check exit codes and output; --write adds once, is idempotent, never removes.
  • The mode decision table: setting × per-file choice × marker × new vs. existing tab, and Go To Definition.
  • Then the manual check list for Bryan, posted on the issue.

Done when pnpm test is green on Node 22 (e2e excluded, as today).

Risks

Import resolution. Projects use package imports aliases and explicit .tsx extensions. The classifier must resolve these, or chained components classify wrong. Covered by the cross-file fixture; the first real project run is the confirmation.
Babel plugin from source. The CLI depends on an internal file of @triplex/client; upstream merges may move it. Keep the import in one place.
Tab-open events. VS Code has no "file about to open" hook, so auto-open swaps a tab right after it opens; a brief flash of source is expected.
Check on other machines. A project's check fails on machines where the install script hasn't run, until someone runs it there.
